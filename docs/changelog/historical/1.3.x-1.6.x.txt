Juanita Banana v1.6.8 Changelog
================================

Changes:
- Implemented Local SOCKS5 Proxy Architecture (port 9151) to intercept WebKit connection requests.
- Resolved Tor SOCKS5 IP-as-hostname lookup failures by converting IP-as-hostname strings into native IP addresses before proxying to Tor.
- Restored native HTTPS and TLS certificate validation for Handshake domains by eliminating URI-to-IP rewriting and HTTP downgrading hacks.
- Enabled seamless Handshake subresource loading (scripts, stylesheets, images) over Tor by resolving Handshake domains locally and tunneling assets securely.
- Intercepted load failures due to TLS errors on Handshake/custom domains (non-system resolvable) to show a custom warning page asking the user if they'd prefer to reload via HTTP, avoiding silent bypasses or standard browser TLS warnings.

Changes:

Juanita Banana v1.6.6 Changelog
================================

Changes:
- Implemented secure trustless local DNS-over-Tor forwarding for Handshake resolution.
  When Tor route-all is active, hnsd runs directly (to perform local SPV validation) and forwards
  outbound nameserver lookup queries to Tor's DNS listener port (dns_listen="127.0.0.1:9053") on localhost.
- Removed torsocks dependency and wrapping features entirely, eliminating UDP loopback connection blocking and P2P connection failures over Tor exit nodes.

Juanita Banana v1.6.3 Changelog

Juanita Banana v1.6.1 Changelog
================================

Changes:
- Fixed a startup race condition where the first tab opened did not synchronize
  with the global webview reference, causing the navigation bar to be unresponsive.
- Pre-emptively kill any orphan hnsd or arti processes on startup to prevent port
  binding conflicts (EFAILURE) when the browser is restarted.
- Fixed the double-free / heap corruption crash (free(): corrupted unsorted chunks)
  by removing unsafe destroy() calls on headless WebViews, allowing GObject to
  manage their lifecycle cleanly.
- Added self-healing configuration: AppConfig::load() now automatically injects the
  "Onion" resolver into the priority list for legacy config files.
- Trimmed src/browsing/gui.rs down to 438 lines (respecting the 500-line threshold)
  by extracting all GTK cleanup triggers into src/browsing/tabs/cleanup.rs.
- Added Cargo compile-time features: default, handshake, tor, just-system,
  all-resolvers, fullsuite. Building with --no-default-features --features just-system
  skips all external daemon building.
- Added scripts/build_torsocks.sh to automatically compile and build a local
  torsocks installation at build time when the tor feature is active.
- Packaged local torsocks and its environment lib into the RPM under /usr/bin/ and
  /usr/lib/juanita-banana/.

Juanita Banana v1.6.0 Changelog
================================

Changes:
- Tor transport implemented via arti subprocess (same lifecycle pattern as hnsd).
- New src/tor/ module: daemon.rs manages arti process, webcontext.rs applies SOCKS5
  proxy to WebKit's WebsiteDataManager.
- New src/resolver/onion/ module: OnionResolver handles .onion v3 addresses — returns
  sentinel IP 127.0.0.2 so policy.rs routes the original URI through the SOCKS5 proxy
  without DNS (onion v3 addresses are self-authenticating).
- arti built at compile time via scripts/build_arti.sh (cargo install arti).
  Non-fatal: browser degrades gracefully when arti is unavailable at runtime.
- HNS-over-Tor: hnsd subprocess wrapped with torsocks when Tor is enabled and torsocks
  is installed; falls back with warning if torsocks not found.
- Config: tor_enabled (default false) and tor_route_all (default false) added to AppConfig.
  Default resolver order updated to [Handshake, Onion, System].
- Config UI: Tor Transport card added to juanita://config -> Resolver Stack tab.
- gui.rs reduced below 500 lines by extracting Tor proxy setup into tor/webcontext.rs.
- build.rs extended: builds both hnsd and arti at compile time when binaries are absent.
- clippy and fmt clean.
- Wiki Overlay-Networks.md updated: Tor status, implementation details, HNS-over-Tor
  current approach vs. Phase 4 in-process arti-client target.
- docs/OVERLAY_NETWORKS.md and docs/FUNCTIONALITIES.md status updated to Done.

Version 1.3.4
-------------
- Implemented dynamic DNS resolution utilizing the user's configured priority chain (Handshake -> System).
- Eliminated static clearnet TLD checklists in favor of checking system DNS resolvability dynamically via `is_system_resolvable`.

- Integrated a thread-safe mapping registry (`RESOLVED_IPS`) to intercept GTK load-changed events and restore original domain names in the address bar.

Version 1.3.3
-------------

- Configured root nameserver to bind explicitly to port 5349 (`-n 127.0.0.1:5349`) and recursive nameserver to port 5350 (`-r 127.0.0.1:5350`).
- Implemented background log readers for `hnsd` daemon process's `stdout` and `stderr` streams.
